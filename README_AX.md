# Sign by Sign · AX 웹 버전

Android 설치형 앱과 서버 없이 실행하는 APK 빌드 방법은 [README_ANDROID.md](README_ANDROID.md)에 있습니다. 이 문서는 기존 웹 실행 방법을 설명합니다.

기존 `prototype.html`을 보존하고, 별도 `prototype-ax.html`에 전체 화면 웹페이지와 실제 SQLite 연동을 추가했습니다. 휴대폰 모형 안에 넣은 화면이 아니라 브라우저 영역 전체를 사용하는 반응형 페이지입니다. 준비된 `prototype-ax.html`을 더블클릭해도 학습·탐색·샘플 인식·복습·기기 내 AI 피드백을 확인할 수 있습니다. 실제 사진 OCR과 최신 SQLite API를 함께 검증할 때는 아래 서버 실행 방식을 사용하세요.

## 바로 열기

Windows 탐색기에서 `prototype-ax.html`을 더블클릭합니다. 독립 실행에 필요한 카탈로그, OCR 워커와 인식 브리지가 프로젝트에 포함되어 있습니다. 브라우저가 `file://` 워커 실행을 제한하면 샘플 결과와 문구 직접 입력은 계속 사용할 수 있고, 실제 사진 OCR은 서버 방식으로 확인하세요.

## 실행

Node.js 22.13 이상이 필요합니다. 현재 작업 환경의 Node.js 24에서 검증했습니다.

```powershell
cd "C:\Users\82108\Desktop\간판탐지\sign-detection"
npm install
npm run assets:ocr
npm start
```

브라우저에서 <http://127.0.0.1:4173/prototype-ax.html>을 엽니다. 현재 폴더에는 패키지 설치와 OCR 언어 파일 다운로드가 완료되어 있어 `npm start`만으로 실행할 수 있습니다. 종료는 서버 터미널에서 `Ctrl+C`입니다. 이미 실행 중이면 서버를 중복 실행하지 마세요.

같은 네트워크의 Android 공기계에서 웹과 APK를 열려면 PowerShell에서 다음처럼 LAN 서버를 실행합니다.

```powershell
$env:SIGN_HOST='0.0.0.0'
node server.mjs
```

`npm` 명령을 사용할 수 있는 환경에서는 같은 동작을 `npm run start:lan`으로 실행할 수 있습니다.

PC의 IPv4 주소가 예를 들어 `203.241.129.163`이라면 폰 브라우저에서 `http://203.241.129.163:4173/`을 엽니다. 첫 화면과 상단의 `Android APK` 버튼으로 `SignBySign-Android.apk`를 받을 수 있습니다. PC와 폰이 같은 네트워크여야 하고 Windows 방화벽 또는 기관망의 기기 간 통신 차단 정책에 따라 접속이 막힐 수 있습니다. 실시간 웹 카메라는 일반 HTTP LAN 주소에서 제한될 수 있으므로 그 경우 사진 선택 또는 설치형 APK를 사용하세요.

카메라 없이 새 여행자 결과 카드를 바로 확인하려면 <http://127.0.0.1:4173/prototype-ax.html?demo=mega>를 열거나 촬영 화면의 `샘플 간판 결과 보기`를 누르세요. 이 샘플은 실제 촬영 결과와 동일한 화면을 사용합니다.

## 미등록 간판 자동 검색

OCR 문구가 SQLite 카탈로그와 일치하지 않으면 더 이상 빈 결과로 끝내지 않습니다. 서버가 네이버 지역검색과 Google Places를 병렬로 확인하고, 찾은 업종을 바탕으로 가게 설명·예상 이용 흐름·바로 쓰는 한국어 문장을 만듭니다. 검색 결과에는 출처 링크와 안내 신뢰도를 표시하며, 지점·영업시간·메뉴는 지도에서 다시 확인하도록 안내합니다.

외부 장소 검색에는 공식 API 자격 증명이 필요합니다. 둘 중 하나만 설정해도 동작하며 값은 파일에 저장하지 말고 서버를 실행하는 PowerShell 세션의 환경 변수로 전달하세요.

```powershell
$env:NAVER_SEARCH_CLIENT_ID='발급받은_클라이언트_ID'
$env:NAVER_SEARCH_CLIENT_SECRET='발급받은_클라이언트_SECRET'
# 또는
$env:GOOGLE_PLACES_API_KEY='발급받은_Google_Places_API_KEY'
node server.mjs
```

- 네이버: [지역 검색 API](https://developers.naver.com/docs/serviceapi/search/local/local.md)
- Google: [Places Text Search API](https://developers.google.com/maps/documentation/places/web-service/text-search)

API 키가 없거나 검색 결과가 없어도 사용을 막지 않습니다. 자주 보이는 브랜드·업종 사전과 OCR 키워드로 가능한 범위의 안내를 만들고, 업종을 확정할 수 없으면 `여기는 뭐 하는 곳이에요?`, `가장 인기 있는 게 뭐예요?`, `카드로 결제할 수 있어요?` 같은 범용 문장과 네이버·Google 지도 검색 링크를 제공합니다. `빽다방`처럼 사전에 포함된 일반 브랜드는 API 키 없이도 카페 안내가 나옵니다.

`npm install`과 `npm run assets:ocr`에는 인터넷 연결이 필요합니다. OCR 실행 시에는 프로젝트에서 제공하는 워커·WASM·한국어/영어 언어 파일을 사용하며 외부 OCR API로 사진을 보내지 않습니다. `node_modules/`, `ocr-data/`는 Git에서 제외했습니다. 다른 컴퓨터에서는 위 준비 명령을 다시 실행하세요.

## 화면과 동작

- 첫 실행: 한국어가 기본 선택된 언어 화면 → 한국어·영어·일본어 중 선택 → 온보딩. 이후 상단 언어 버튼으로 즉시 변경합니다.
- 학습 홈: 4개 분야 사진 카드, 세부 분류 선택, 해당 분야 학습 시작, 중단한 학습 이어가기.
- 간판 둘러보기: 검색, 분야·세부 분류 필터, 간판 사진과 뜻 상세보기, 사진 출처·라이선스 확인.
- 학습: 모바일 전체 화면 간판, 좌우 스와이프, 뜻 보기, 사진 확대·이동, 버튼/키보드 대체 조작, 되돌리기, 세션 요약. 왼쪽은 다시 볼 간판, 오른쪽은 이해한 간판으로 기록합니다.
- 복습: 왼쪽으로 넘겼거나 촬영 결과에서 저장한 간판을 다시 학습합니다.
- 간판 촬영: 상단의 작은 카메라 아이콘 → 휴대폰 후면 카메라 촬영 → 자동 문자 읽기 → DB 문구 대조 → 장소·가게명, 업종, 쉬운 설명, 기대할 수 있는 경험, 바로 쓰는 한국어 안내. 사진 선택과 문구 직접 입력도 지원합니다.

개인 학습·복습 기록은 같은 브라우저의 `localStorage`에 저장합니다. 기존 원본 프로토타입의 기록이 있으면 현재 등록된 간판에 해당하는 기록을 별도 AX 저장 공간으로 이관하며 원본 기록을 지우지 않습니다. 새 간판 제보와 공동 확인은 별도로 서버 SQLite에 저장되므로 같은 서버를 사용하는 다른 브라우저에서도 볼 수 있습니다.

## 여러 사용자 공동 학습

웹 서버는 `POST /api/community/contributions`, `GET /api/community`, `POST /api/community/contributions/:id/vote`를 제공합니다. 사용자 A가 동의 후 새 간판을 제보하면 즉시 공동 확인 대기 목록에 나타나고, 사용자 B가 정보를 확인하면 서로 다른 2명의 확인을 충족해 공개 카테고리 카드로 승격됩니다. 공개된 이름은 `/api/catalog`과 `/api/match`에도 합쳐져 이후 사용자가 같은 간판을 검색하거나 촬영했을 때 공동 학습 결과로 인식됩니다.

브라우저마다 익명 장치 ID를 생성하고 서버에는 해시만 저장해 중복 확인을 막습니다. 사진은 명시적 동의가 있는 제보에서만 검토용으로 저장하며 공개 카드에는 실제 제보 사진 대신 기존 분류 대표 이미지를 사용합니다. 현재 방식은 신경망 모델을 즉시 재훈련하는 것이 아니라, 검증된 간판 이름·별칭·카테고리를 공동 카탈로그와 매칭 데이터에 추가하는 방식입니다.

## 데이터베이스

실제 파일은 `data/signs.sqlite`, 초기 데이터는 `data/seed.json`과 `data/travel-guides.json`입니다. 기본 카탈로그 테이블과 함께 공동 제보·사용자별 확인 투표 테이블을 사용합니다.

| 분야 | 세부 분류 | 초기 간판 수 |
| --- | --- | --- |
| 의료 | 약국, 병원, 내과, 소아청소년과, 치과, 안과 | 6 |
| 카페 | 메가커피, 스타벅스, 커피숍 | 3 |
| 교통 | 지하철 입·출구, 버스정류장, 택시 승강장 | 3 |
| 음식점 | 한식집, 중식집, 일식집, 프랜차이즈 식당 | 10 |

총 16개 세부 분류와 22개 학습 카드입니다. 의료 6개 세부 분야와 교통 3개 분야에는 각각 중복되지 않는 이미지 3장씩을 제공합니다. 음식점에는 롯데리아와 함께 맥도날드·서브웨이·배스킨라빈스·요아정·KFC·버거킹을 추가했습니다. 이미지 바이너리는 `assets/`에 두고 SQLite에는 경로·유형·작성자·출처·라이선스·해시를 저장합니다.

데이터를 추가하려면 이미지 파일을 추가하고 `data/seed.json`의 분류/간판/언어별 뜻/별칭을 수정한 뒤 다음 명령을 실행합니다.

```powershell
npm run db:seed
```

이 명령은 등록 항목을 추가·갱신합니다. seed에서 제거한 ID를 DB에서 자동 삭제하지는 않습니다. 새 이미지도 실제 사진인지 학습용 그림인지 구분하고, 재사용 권리와 출처 정보를 함께 등록하세요.

## 사진과 제작 이미지

Wikimedia Commons에서 재사용 조건이 확인된 병원·교통·프랜차이즈 실제 사진을 가져왔습니다. 가져오기 스크립트는 SHA-256 해시로 중복 파일을 거르고, 출처·저작자·라이선스·크기를 `data/photo-sources.json`에 기록합니다. 간판이 흐리거나 자유로운 재배포 조건을 확인할 수 없는 분야는 실제 사진인 것처럼 표시하지 않고 별도의 학습용 예시 이미지를 사용합니다.

생성 이미지는 의료 세부 분야 보강과 요아정 학습 예시에 사용합니다. 그림은 실제 지점 사진으로 표시하지 않으며, 브랜드와의 제휴를 뜻하지 않습니다.

- 새 그림: `assets/ax/generated/` — 메가커피, 한식, 중화요리, 일식, 롯데리아, 버스정류장, 택시 승강장.
- 사진: `assets/ax/photos/`.
- 사진 원본·저작자·라이선스: `data/photo-sources.json` 및 웹페이지의 사진 출처 화면.
- 생성 방식과 최종 프롬프트 세트: [generation-prompts.md](data/generation-prompts.md). imagegen 스킬의 built-in 이미지 생성 방식으로 만들고 한글 표기를 검수했습니다.

네이버·Google 지도는 간판 상세와 촬영 결과에서 외부 검색 링크로 연결합니다. Google Street View 이미지 저장·캐싱 제한은 [공식 정책](https://developers.google.com/maps/documentation/streetview/policies)을 따릅니다. 네이버 로드뷰 사진의 재배포 권한은 이번 작업에서 확인되지 않아 다운로드·DB 저장하지 않았습니다. 지도 화면을 캡처하거나 그대로 따라 그린 파일도 포함하지 않았습니다. 지도 사진의 적법한 저장 권한이 확보되면 같은 이미지 테이블에 출처를 추가하는 방식으로 확장할 수 있습니다.

라이선스 사진을 다시 확보하려면 `npm run assets:photos`를 실행합니다. 명시된 Commons 파일만 가져오며 출처 메타데이터를 함께 기록합니다. 개별 사진의 CC BY-SA 조건은 해당 사진에 적용되며 프로젝트 전체에 같은 라이선스를 부여한다는 의미는 아닙니다.

## 촬영 결과의 의미와 한계

사용자 확정 범위는 **업종·브랜드와 간판 뜻**입니다. 특정 지점·주소·영업시간·현재 영업 여부나 실제 점포의 진위를 판별하지 않습니다.

1. 브라우저의 Tesseract OCR로 한국어와 영어 글자를 읽습니다. 사진은 메모리에만 두며 서버에 업로드하거나 DB에 저장하지 않습니다.
2. 인식한 문구만 같은 서버의 `POST /api/match`로 전달합니다.
3. 정규화한 글자와 등록 별칭을 대조합니다. 수동 확인 문구 또는 OCR 신뢰도 75 이상에서 단일 정확 문구가 있으면 ‘등록 문구 일치’로 표시합니다.
4. 낮은 신뢰도, 오타, 긴 상호명, 복수 간판은 후보를 보여주고 사용자 선택을 받습니다. 없는 문구는 미등록으로 안내합니다.

이는 **사진 자체가 동일한지 확인하는 이미지 매칭 모델이 아닌 OCR 기반 문구 조회**입니다. OCR 신뢰도는 실제 정확도 보장이 아닙니다. 기울기·야간·가림·작은 글자·다른 간판 혼입으로 오인식할 수 있으므로 결과의 문구를 확인하고 필요하면 영역을 좁히거나 수정하세요. 모든 촬영 사진의 100% 정확한 식별은 보장하지 않습니다.

## 스마트폰 카메라와 배포

실시간 `getUserMedia` 카메라는 브라우저 권한과 보안 컨텍스트가 필요합니다. 같은 PC의 localhost는 사용할 수 있지만, 휴대폰에서 PC의 일반 HTTP LAN 주소로 접속하면 실시간 카메라가 차단될 수 있습니다. 이 경우 ‘스마트폰으로 촬영’ 파일 입력 또는 사진 선택으로 이어갑니다. `capture="environment"`는 기기·브라우저에 따라 카메라 대신 파일 선택 화면을 열 수도 있습니다.

실제 서비스는 신뢰할 수 있는 인증서의 HTTPS로 배포하세요. 기본 서버는 외부에 공개하지 않고 `127.0.0.1`에만 연결됩니다. 배포 환경에서는 `SIGN_HOST`, `SIGN_PORT`를 설정할 수 있고(기존 `HOST`, `PORT`도 호환), `SSL_CERT`, `SSL_KEY`를 둘 다 지정하면 HTTPS 서버를 실행합니다. 인증서 구매, 배포, 방화벽 변경, 카메라 권한 부여는 이번 작업에서 수행하지 않았습니다. 휴대폰 실기기 카메라 QA는 HTTPS 배포 후 별도로 필요합니다.
